# Performance Notes

## Current prototype budgets

The prototype prioritizes clarity and proof of architecture over absolute throughput.

Default settings:

| Item | Current value |
|---|---:|
| Chunk cell resolution | `32³` |
| Density sample grid | `33³` |
| Cell size | `1m` |
| Chunk world size | `32m` |
| Base SDF stream radius | `7` horizontal chunks |
| High-altitude SDF stream radius | up to `20` horizontal chunks |
| Runtime max SDF stream radius | `20` horizontal chunks / about `640m` |
| Far vista radius | `~5.8km` concentric heightfield clipmap rings at `12/24/48m` spacing |

| Vertical layers | `-1, 0, 1, 2` |

On a modern desktop, the first load should progressively fill in terrain rather than blocking the main thread. The widened SDF ring is prioritized from near to far and throttles new chunk requests per frame. The additional `y=2` vertical layer prevents high ridges and mountains from being clipped when viewing the world from above. Lightweight camera-centered heightfield clipmap rings fill the long-distance horizon immediately, so flying upward shows a much larger landscape without forcing every distant tile through the volumetric mesher. Radius 20 is intentionally available for high-end desktop testing; radius 7 remains the safer default.

The settings panel includes auto, low, balanced, high, and ultra quality presets. Auto maps the current browser capability signals, worker/SAB readiness, CPU concurrency, and optional device-memory hint onto the existing preset tiers, then watches rolling average and p95 frame time after a warmup window. Sustained slow frames downshift the active tier, sustained fast frames can upshift it after a cooldown, and the overlay reports the active tier, pressure state, frame-time summary, and capture count. Presets adjust stream radius, material detail, fog density, exposure, atmosphere strength, water opacity, and vegetation enablement as a coarse capability tier, then leave the individual controls editable for profiling and manual tuning. The panel is collapsed by default for the reference-oriented first view, the center crosshair is hidden, game markers and the brush preview marker are opt-in so visual captures are not dominated by editor gizmos. The engine-settings storage key is now `stormCanyon.engineSettings.v20`, which lets the higher pulled-back overlook camera, low-sun, atmosphere, fog, water, forest, SDF focus-streaming, far-vista horizon AO, and material-detail defaults replace stale visual settings while leaving region data untouched.

The first better-chunk milestone is now in place: chunks keep the same `32m` world footprint but sample at `32³` cells / `33³` density points with `1m` cells. The mesher now uses a Marching Cubes cube-edge polygonizer with face-contour loop extraction, a center-value ambiguous-face decider, standard `x`, `y`, and `z` cube-edge crossing caches, and density-grid-derived normal interpolation instead of emitting tetra diagonal topology or resampling the full SDF for every vertex normal. The origin smoke-test chunk currently emits about `4.0k` triangles before edits, substantially below the previous marching-tetra output.

The terrain shader now uses packed biome/wetness/snow mask bytes plus a fast hash-based value-noise/fBm/domain-warp stack rather than sine hashing. Those three bytes remain ABI-stable but now fold in deterministic macro continent/moisture/temperature fields, heuristic drainage accumulation, erosion exposure, and vegetation suitability. The native ABI exposes climate probes for smoke tests and tooling, while the far heightfield uses the mirrored TypeScript functions before packing the same mask lane. The shader procedurally synthesizes material detail for grass, dirt/mud, rock strata, lichen, and snow directly in WGSL, so it improves visual richness without adding texture downloads.

The first visual-quality foundation slice adds one fullscreen sky draw, a fourth scene-uniform vec4 for visual controls, shader-side tone/atmosphere helpers, hybrid SDF-near/scenic-far river water, opt-in game markers, smaller near-tree defaults, a deterministic renderer-side far-forest patch, renderer-only alpine snow caps, and scenic far-vista shaping. The latest reference-alignment pass uses `12/24/48m` far-vista rings over about `5.8km`, moves the default camera to a higher pulled-back valley overlook, enables near SDF terrain by default, and adds a bounded ground-focus stream anchor so high-overlook captures still load editable SDF terrain near the look target. It retunes exposure, atmosphere, fog, material detail, water opacity, low-sun haze, snow/grass color preservation, and water color; adds CPU-baked directional horizon AO/cavity shading for far-vista vertices; makes water opaque/depth-writing; smooths the SDF/scenic river height blend; lowers the foreground review ponds; opens near-river vegetation; and keeps game/brush markers opt-in for the supplied alpine screenshot. This pass is intentionally renderer/default focused and did not change the mirrored physical terrain-height function. It is still below the reference image until the follow-on visual-quality pipeline adds real shadow maps/AO, richer material art direction, terrain-integrated lakes/water depth, broader scenery/impostors, and production sky/water work.

The cave field is now a deterministic SDF graph seed rather than a single tunnel: a canyon-following trunk is smoothly unioned with spaced side branches, branch-end chambers, and optional vertical shafts. The added field is intentionally sparse to avoid Swiss-cheese terrain, but it changes quantized density hashes and some cached-edit sample counts, so `docs/mesh-quality-baseline.json` was refreshed through `npm run mesh:regression -- --update`. The smoke test also verifies the `get_cave_distance` probe stays finite and bounded. The runtime also keeps an initial IndexedDB-backed cave graph tile cache that mirrors those formulas into stable trunk/branch/shaft passage IDs, chamber IDs, biome hooks, nearest-feature probe distances, schema/generator-compatible persisted records, worker-adopted native replacement tiles, and overlay/export telemetry. The native core now exposes the same graph through fixed-field passage/chamber arrays so smoke, worldgen regression, and idle browser workers can validate or adopt native graph counts against TypeScript counts. This metadata path still does not replace native SDF evaluation or provide production cave graph streaming ownership.

The runtime worldgen tile cache is a diagnostic cache, not a meshing or final production cache. It stores bounded `256m` tiles at `17x17` resolution for elevation, macro climate, drainage, erosion, vegetation, local gradient-flow direction, multi-scale flow accumulation, drainage basin ID, stream order, channel width, stream power, biome/wetness/snow masks, material IDs, normalized grass/rock/snow/mud material weights, terrain-surface cave distance/influence, dominant biome IDs, normalized biome-blend weights, river-network IDs, and river/lake classification. Live camera and brush probes use those cached 2D fields plus a direct signed cave-distance sample, the initial erosion tile cache's thermal/hydraulic erosion, deposition, sediment, bedrock, soil, and vegetation-retention fields, the material-field cache's roughness, fertility, stability, shoreline, cave-surface, route-cost, and blend-confidence fields, and the cave graph cache's nearest passage/chamber metadata. The frame loop prewarms the camera-centered `3x3` worldgen, erosion, material-field, and cave graph tile neighborhoods only when the camera enters a new tile. Cache misses still generate TypeScript fallback worldgen tiles, erosion tiles, material-field tiles, and generated cave graph metadata synchronously so probes never wait on storage or worker throughput; the worldgen cache then attempts an asynchronous IndexedDB load for schema/generator-compatible native tiles, queues native WASM tile replacements when needed, reprioritizes queued work for live samples and export captures, drops stale low-priority prewarm requests from old camera neighborhoods, pumps those jobs only when terrain workers are idle, adopts returned native arrays in memory, and saves adopted native tiles back to the bounded worldgen tile store. The erosion cache now follows the same persistence and worker-adoption shape for erosion fields: it attempts schema/generator-compatible IndexedDB loads, queues prioritized native WASM erosion tile replacements when terrain workers are idle, adopts returned field buffers in memory, persists adopted native tiles to `src/erosion_tile_store.ts`, invalidates incompatible records, prunes oldest retained records, and reports request/response/queue/adoption/native-byte/persistence telemetry. The material cache follows that same fallback/adoption shape for material fields: it composes immediate TypeScript tiles from live worldgen, erosion, and cave graph caches, attempts schema/generator-compatible IndexedDB loads, queues prioritized native WASM material tile replacements when terrain workers are idle, adopts returned field/ID buffers in memory, persists adopted native tiles to `src/material_tile_store.ts`, and reports request/response/queue/adoption/native-byte/persistence telemetry. Production hydraulic/thermal erosion simulation, final production material-field ownership, and broader region/world invalidation policy remain future work. The cave graph cache similarly loads schema/generator-compatible records from its own bounded IndexedDB store, queues native passage/chamber-buffer replacements for idle terrain workers, reprioritizes live probes and export captures, adopts returned graph tiles in memory, and persists adopted graph tiles for later sessions. Compatible persisted worldgen, erosion, material, and cave graph tiles remove redundant queued replacement work before dispatch. Persistent tile stores prune oldest records beyond retention caps and invalidate incompatible records before the caches treat them as misses. Overlay and export artifacts report cached tile count, native tile count, persisted tile count, hits, misses, evictions, generated tiles/samples, prefetch centers/touched tiles, worker requests/responses/pending/queued/rejections, queue best priority, queue drops, queue reprioritizations, adopted native tiles, transferred worker bytes, persistence loads/hits/misses/pending/saves/failures/invalidations/prunes, retained records, persisted bytes, erosion tile cache/native/persistence stats, material-field cache/native/persistence stats, cave graph passage/branch/chamber/shaft counts, cave graph hits/misses/evictions, cave graph prefetch/generation counters, cave graph persistence loads/hits/misses/pending/saves/failures/invalidations/prunes, and persisted cave graph bytes so future production tile ownership can be compared against the current diagnostic path. The WASM core exposes the native worldgen single-tile buffer with the same scalar field order and ID arrays, the native erosion tile buffer with 11 scalar field slots, the native material tile buffer with 12 scalar field slots plus dominant material IDs, and a native cave graph tile buffer with passage/chamber field arrays; the smoke test verifies tile dimensions, finite fields, normalized masks/weights, material-weight sums, cave-distance finiteness, drainage-network field ranges, ID ranges, erosion field ranges, material field ranges, and cave graph field ranges. The settings panel can export the current camera-centered `3x3` tile neighborhood as JSON with export schema plus tile schema/generator versions, nested erosion tiles, nested material-field tiles, and nested cave graph tiles for local review, and `npm run worldgen:regression` compares deterministic TypeScript worldgen, native worldgen, TypeScript erosion, native erosion, TypeScript material fields, native material fields, TypeScript cave graph, and native cave graph scene summaries plus worldgen/erosion/material/cave graph worker-queue priority and erosion/material persistence behavior against `docs/worldgen-tile-baseline.json`.

Material painting now rides on the same edit-log replay path as terrain sculpting. Paint operations use the current sphere, box, or capsule brush shape and dirty the same intersecting chunks, but workers skip density-grid mutation for paint edits. During `mesh_cached_chunk` or full `generate_chunk`, the WASM vertex classifier applies the latest paint override to the material-ID byte while preserving the quantized density samples. The smoke test verifies that a full-chunk paint changes material bytes without changing the cached density grid.

Carve/build falloff now uses the same edit-log replay path as hard sculpting. Falloff is stored on carve/build edit operations only, remains optional for imported legacy saves, expands the dirty-region radius conservatively, and applies smooth SDF subtraction/union in WASM for generated chunks and cached `33³` density remeshes. The old hard-edit exports remain available for compatibility; falloff-specific exports cover sphere, box, and capsule sculpting.

Smooth editing now uses the same brush shapes and dirty-chunk path as sculpting. The WASM core applies smooth edits in log order after procedural sampling or against cached density pages by copying the active `33³` grid to scratch storage, blending affected samples toward their 6-neighbor average, and then polygonizing the result.

Flatten editing is now another density-changing edit in that path. It blends affected samples toward the horizontal plane at the brush center, uses the same persisted brush-strength setting as Smooth, supports sphere, box, and capsule brushes, and makes capsule flattening the current path/terrace-cut primitive while preserving deterministic cached-density remeshing.

The runtime overlay now reports rolling frame time, last/average upload MB, renderer upload-ring staging pages, worker queues, chunk states, mesh overflow events, edit-log usage, compressed chunk-cache entries/hits/misses, adaptive quality state, live camera/brush worldgen probes including erosion tile fields, signed cave distance, and cave graph nearest-feature metadata, worldgen tile-cache pressure, erosion tile-cache pressure, cave graph tile-cache pressure, and estimated GPU buffer memory by terrain, far terrain, vegetation, water, and upload-staging categories. These are estimates from known uploaded buffer sizes, not hardware GPU memory counters. Diagnostic UI refresh is throttled and deferred during camera movement; overlay probes use cheap procedural samples so moving into uncached worldgen tiles does not force synchronous fallback tile generation. Terrain debug views can switch the shader to normals, material IDs, combined material masks, individual biome/wetness/snow mask channels, AO, or chunk ID coloring without changing mesh data, and the density debug panel reads configurable cached `33³` SDF slices without triggering chunk regeneration. Brush/falloff presets and procedural paint-material picking are settings-only editor operations until the user applies an edit, so profiling changes are visible before they mutate chunk data. Captured slices persist in bounded named localStorage sets with JSON import/export, current-vs-capture numeric diff telemetry, and a diff heatmap as diagnostic snapshots, not as engine storage. The same exported JSON can be compared by `npm run density:diff` with thresholded changed-cell, mean-delta, and max-delta checks. Export Diagnostic creates a heavier JSON artifact that embeds the current canvas PNG with settings, profiler, streamer, region, worldgen probes, density-diff context, auto-quality state, and recent quality captures for screenshot-linked browser investigations. Export Quality creates a smaller JSON artifact focused on preset tier, frame-time samples, renderer/streamer pressure, worldgen probes, capability state, and recent auto-quality adjustments.

Runtime checks can now be driven directly through query-string automation. `set.<EngineSettingsKey>=...` and `settings.<EngineSettingsKey>=...` apply sanitized settings at load time, `camera=x,y,z,yaw,pitch,fov` positions the camera, and `auto`/`autoActions` can run state, diagnostic, quality, worldgen, browser-worker benchmark, reload, carve, density, region, and reset-game actions without UI clicks. `test.move` drives deterministic key movement, and `test.frameProbe=1` records per-frame section timings on `window.__stormCanyonFrameProbe` for stutter diagnosis. Reports emit as single-line `STORM_CANYON_AUTOMATION` console JSON, can be mirrored onto `window.__stormCanyonAutomationLatest`, and can be POSTed to `/__storm/automation-report` so Vite dev/preview or the static server writes `output/automation/latest.json` plus timestamped report files. The settings panel also exposes panel visibility toggles for the overlay, settings panel, density panel, and region browser; the same toggles are URL-addressable for clean screenshot and validation runs.

The renderer now derives meshlet-like cluster bounds for every uploaded near-terrain chunk and uploads those bounds into GPU storage buffers. The CPU still performs chunk-sphere rejection and computes overlay-visible cluster counts, then groups frustum-visible clusters into contiguous index ranges. When the previous-frame Hi-Z pyramid is stable, the renderer uploads conservative range bounds plus initialized range-level `drawIndexedIndirect` records, and a WebGPU compute pass tests those range bounds against the frame frustum and depth pyramid before preserving or zeroing each indirect record. When Hi-Z is not stable, the render pass uses the same contiguous CPU-visible ranges as direct indexed draws, which reduces command pressure during camera movement and warmup without relying on stale depth. Fixed indirect-slot replay is capped more aggressively while the camera is moving to avoid JavaScript command-encoding spikes until a draw-count or multi-draw path replaces replay. The overlay reports visible/culled clusters, submitted cluster-range batch draw calls, frustum-culled clusters, and GPU-readback Hi-Z tested/culled range batches. This is now GPU-assisted range-batched Hi-Z occlusion and indirect draw generation, but not yet fully GPU-owned visible-cluster compaction, WebGPU multi-draw submission, or a production terrain draw arena.

After the main render pass, the renderer now builds a farthest-depth Hi-Z pyramid into an `r32float` texture chain from the `depth32float` depth attachment. The next frame samples that pyramid only when the view-projection matrix is stable enough to avoid camera-motion artifacts. The cull shader projects each cluster-range bound, selects a conservative mip for the screen rectangle, samples the covered mip cells, and zeroes the indirect draw only when all sampled depth is closer than the range's nearest projected depth with bias. Runtime profiling reports the pyramid mip count and estimated memory beside the existing terrain, vegetation, water, and upload-ring memory estimates.

Vegetation patches now retain worker-generated instance arrays on the CPU with patch bounds derived from the same data. The renderer CPU-culls those patch bounds against the frame frustum, applies distance LOD at the instance level for shrubs, rocks, and small pines, packs the surviving instances into one transient GPU vertex buffer, and draws the visible vegetation/scenery set with a single instanced batch draw. The overlay and quality captures report visible/culled patch counts, rendered vegetation instances, instance LOD-cull counts, and batch-draw counts so later GPU culling, impostor, or scenery expansion work can be measured against the same telemetry.

The overlay also reports the runtime capability tier: WebGPU state, cross-origin isolation, SharedArrayBuffer availability, current worker buffer mode, max WebGPU buffer size, timestamp-query support, and device-loss state. When cross-origin isolation is active, generation jobs use per-worker SharedArrayBuffer queue pages that hold small batches of procedural chunk descriptors. Workers process those batches after one wake message, using non-overlapping shared result-arena slots for each batched result when the payload fits. Cached-density remesh jobs still copy their `33³` `Int16Array` density inputs into per-worker SharedArrayBuffer pages. Renderer upload consumes shared result views directly, and cache entries can borrow the same slot-backed mesh, density, and vegetation views with an explicit release callback that returns the slot on cache eviction, invalidation, or failed insertion. Oversized results, exhausted slots, and non-borrowable payloads still fall back to transferable buffers or owned cache copies. Overlay telemetry reports shared queue pages, generated jobs, generated batches, maximum observed batch size, remesh dispatches, zero-copy renderer result count, cache-borrowed payload volume, and cache copy fallback volume.

Near and far terrain uploads now use chunk-local quantized positions plus packed normal/AO/material/mask attributes. Each terrain draw binds a small origin/scale instance buffer, so the shader reconstructs world position from `unorm16x4` local coordinates instead of reading `float32x3` world positions from every vertex. Generated chunks are written directly by WASM in that packed layout and cross the worker boundary without a main-thread repack; the far-heightfield builder still creates float vertices locally, then packs the same enriched biome/wetness/snow mask lane before upload.

The native chunk ABI is now LOD-scale-aware, and the settings panel can enable experimental mixed-LOD near-terrain streaming. `generate_chunk` and `mesh_cached_chunk` configure cell size from the requested LOD, keep base-grid chunk origins stable, and report the active LOD, cell size, chunk world size, and coarse-edge seam mask through worker stats. `src/terrain_lod.ts` owns the deterministic selector used by streaming: when LOD rings are enabled, it keeps the inner radius at LOD 0, uses an intermediate LOD 1 ring, uses an LOD 2 outer ring at larger radii, downgrades aligned coarse blocks when they would cross into a finer inner ring, classifies coarse-to-fine x/z seam masks, and emits an explicit transition-face schedule, per-base-cell transition worklist, deterministic transition sample/case metadata, and a deterministic table-driven transition-prism mesh. The streamer clears live terrain when the toggle changes so stale chunks do not overlap the new selection. Cache/editor sphere tests use the stored terrain frame scale where available. Runtime now samples cached density payloads on both sides of coarse-to-fine borders, builds a single aggregate packed transition mesh, submits it through the terrain renderer, and reports emitted/missing transition cells, triangles, and whether the current aggregate came from the native worker or TypeScript fallback in the overlay/export stats. The native WASM core also exposes a 12-sample transition-prism cell mesher ABI for all four horizontal seam sides, writing standard packed terrain vertices/indices and smoke-testing bounds, overflow state, and index ranges; the browser queues sampled transition cells to an idle terrain worker and swaps in the native-packed aggregate result over the TypeScript fallback. The renderer still appends conservative vertical skirts on classified coarse borders as a crack-hiding fallback. This is a runtime/native bridge and contract for the later full Transvoxel replacement, while the mesh-quality baseline includes an LOD-1 procedural capture and `docs/lod-selection-baseline.json` covers selector/seam/transition-schedule/cell-worklist/case/table-mesh summaries so future transition mesh generation has regression targets.

Renderer buffer creation now routes most vertex, index, instance, and cluster-bound payloads through mapped upload-ring pages. A frame flush unmaps pages, copies staging ranges into final GPU buffers, submits the copy work before render commands, and remaps pages asynchronously for reuse. If all pages are busy or a payload is too large, the renderer falls back to mapped-at-creation buffers and reports the fallback count/bytes. Buffer destruction now goes through the upload ring as well, so chunks or marker buffers removed before the next flush are destroyed only after their pending copy destination has been submitted. This is the first upload-ring foundation; page sizing and copy batching still need tuning from browser traces.

Near chunk density samples are stored as signed 16-bit SDF values at a `256` samples-per-meter scale. Workers copy those `33³` samples with each chunk result, and the cache keeps them beside the packed render mesh as the basis for future remeshing and persistence.

Region persistence compresses chunk payloads before writing them to IndexedDB or `.scvr` files. Density samples use delta-varint encoding, while packed vertices, indices, and vegetation use byte-LZSS only when it beats raw bytes. The live chunk cache still keeps decoded typed arrays so rendering and cached remeshing remain direct; compression cost is paid only on save/export and decompression cost is paid only on load/import.

The overlay reports persistence compression as encoded/raw megabytes and percent smaller, and selected region slots expose saved chunk/edit counts, save time, and raw/LZSS/delta-varint payload counts under their current display names. The region browser also summarizes aggregate saved-slot storage and has named retention policies with custom max-slot/max-MB controls, an always-visible dry-run summary, an explicit preview action, a bounded local maintenance history, searchable metadata-only payload inspection, saved-vs-saved payload comparison, decode/hash payload verification, and JSON maintenance-report export with inspected/comparison/audit payload metadata before pruning the oldest managed saves while preferring non-active slots when possible. The selected slot can be compared against the active world state through a lightweight diff that reports chunk coverage, changed common chunk fingerprints, signature-aware same-ID edit changes, active-only and saved-only edit samples, and branch signature differences, while the payload browser compares two saved slots directly from IndexedDB metadata to show common/missing chunks, encoded/raw byte deltas, codec changes, and largest changed payloads without decoding full mesh arrays. The Verify action decodes each persisted vertex, index, density, and vegetation payload for the inspected slot, validates typed-array alignment, records encoded and decoded FNV hashes, highlights failures, and reports largest decoded chunks. `.scvr` files can be decoded into a pending import preview with the same active-vs-file telemetry before the user applies or merges it. This is telemetry for tuning codecs, identifying oversized saves, and catching stale slots; stronger production cache ownership and larger saved-region analysis remain future work.

The chunk cache now releases evicted or cleared owned payload arrays into a bounded typed-array pool, and releases borrowed shared-result slots through the slot owner instead of pooling aliased arrays. Region load/import decoders acquire from that pool when sizes match, which reduces repeated allocation churn across save/load/debug cycles while keeping the live cache in decoded typed arrays. Workers also use a small scratch arena for reusable temporary staging, per-worker shared result arenas for normal chunk outputs, and transferable buffers only as fallback. Overlay pool, worker-scratch, shared job-page, shared remesh-page, and shared result-page counts show whether restores, worker jobs, generate dispatches, cached-density remesh dispatches, zero-copy renderer/cache result consumption, and cache copy fallbacks are reusing stable memory or allocating new arrays.

The WASM ABI now has a `mesh_cached_chunk` path that polygonizes the current density buffer without rerunning procedural density sampling, plus `get_mesher_id()` so host-side tests can verify the active mesher family. The smoke test verifies the cached-density remesh preserves the generated mesh vertex count for the origin chunk, validates triangle-list index ranges, and covers sphere, box, capsule, falloff, smooth, flatten, and paint edit application. `scripts/mesh-regression.mjs` extends that into a deterministic topology/hash baseline for procedural chunks, cached edit remeshes, and synthetic density fields, including falloff-, smooth-, and flatten-edit captures. Runtime carve, build, smooth, and flatten rebuilds use this path for dirty chunks when their cached density samples are available.

The brush workflow now exposes placement distance alongside radius, mode, shape, capsule length, carve/build falloff, brush strength, and paint material. The settings panel includes color swatches that switch directly into paint mode and compact Detail, Path, Terrace, Tunnel, Hard, and Soft presets that update the same persisted brush settings as the sliders/selects. It also persists up to 12 locally named brush presets in `localStorage`; each preset stores only the existing brush settings, can be applied without new worker contracts, and can be deleted without touching edit history or saved regions. The live preview marker, settings-panel brush inspector, and `E` brush action use the same sanitized distance and falloff-aware influence radius, which keeps edit placement deterministic while allowing closer cave cuts, farther terrain sculpting, softer carve/build blends, density smoothing, flatten/path cuts, terrace cuts, tunnel cuts, or material repainting without changing camera movement. The inspector samples cached worldgen/erosion/cave fields at the brush target and renders key-deduplicated influence, material-weight, biome-weight, and terrain-mask bars, so visible falloff/material tuning does not add worker synchronization. The settings panel also renders a compact edit-history section from the same in-memory edit log, redo stack, and capped branch archive; it updates through a key-deduplicated DOM path each frame, so visible history inspection and branch summaries do not alter chunk rebuild semantics or add worker synchronization. Switching a branch replaces the active edit log and triggers the same full visible rebuild path as undo/redo.

The region store persists the current edit log, redo stack, archived edit branches, expedition game progress, and cached chunk payloads through IndexedDB slot records, and the same snapshot can be exported to or imported from a portable `.scvr` file. Expedition progress now includes survey beacons, field contracts, route checkpoints, clearable hazards, and traversal distance; localStorage mirrors the same `stormCanyon.gameProgress.v2` shape for normal reloads while older v1 survey/contract saves still sanitize into the current shape. The deterministic benchmark harness runs the same WASM core without the browser renderer:

```bash
npm run benchmark
```

It covers three fixed scenes and reports average full generation, cached remesh, sphere carve/build remesh, box carve remesh, capsule build remesh, smooth remesh, and flatten remesh timings. Set `BENCH_JSON=1` to emit machine-readable results for later CI or trend tracking.

The settings panel also exposes a `Worker Bench` action that runs the same deterministic scene family inside a dedicated browser worker. Those captures use the actual browser WebAssembly/runtime path without touching the live chunk-streaming worker pool. Recent captures are stored locally, compared against the previous capture as a faster/similar/slower trend, shown in the overlay, recorded in maintenance history, and embedded in Export Diagnostic and Export Quality JSON artifacts so quality-tier decisions have both frame-time and worker-throughput evidence. The same panel can export, import, or clear the browser-worker benchmark history; imports merge by benchmark ID and recompute trends so captures can move between machines without losing readable deltas.

Portable browser-worker benchmark histories, quality captures, and diagnostic captures can be compared in local review or CI with:

```bash
npm run benchmark:review -- baseline-benchmarks.json candidate-benchmarks.json --report output/benchmark-review.json
```

The review script extracts the latest browser-worker benchmark capture from either artifact shape, compares top-level generation/remesh timings and per-scene timings, and fails when configurable overall, metric, or scene regression thresholds are exceeded.

The mesh-quality baseline can be checked or intentionally refreshed with:

## Known hotspots

- The current Marching Cubes contour path has deterministic mixed-LOD terrain-ring selection, an explicit transition-face schedule, a per-base-cell transition worklist, deterministic transition sample/case metadata, a table-driven transition-prism mesh baseline, a native transition-cell ABI, idle-worker native aggregate transition meshing, a TypeScript fallback transition mesh built from cached density samples, and temporary coarse-edge seam skirts, but still lacks full native Transvoxel transition chunks for LOD seams.
- Density-grid gradients are normalized per grid sample; production work can still tune boundary gradients and promote the current runtime worldgen tile cache, prioritized native tile queue, native tile-buffer ABI, deterministic drainage-network metadata, IndexedDB-backed worker-adopted native erosion tile cache, biome-blend/material weights, cave-proximity fields, macro climate, heuristic drainage/erosion/vegetation material signals, material-paint IDs, deterministic cave-distance field, IndexedDB-backed cave graph metadata, and worker-adopted native cave graph tile buffers into native cached production fields, production erosion/material layers, or production cave graph ownership.
- Near chunks now render from large GPU terrain arenas: shared vertex/index/origin streams, shared cluster/source-indirect records, and a compute-compacted indexed-indirect arena for frustum plus optional previous-frame Hi-Z visibility. Core WebGPU still replays indirect slots individually, so a lower-overhead draw-count/multi-draw submission path is still pending.
- Vegetation patches now share a single visible-instance batch draw after CPU patch culling and instance distance LOD; production work should move culling deeper onto the GPU and add richer impostor/LOD coverage for larger scenery sets.
- Mesh-cache decode is still main-thread work when revisiting evicted chunks.
- Hi-Z occlusion now feeds the GPU terrain compaction pass instead of CPU-frustum-submitted range batches, but it still needs a production multi-draw/draw-count submission path to remove fixed indirect-slot replay overhead.
- Benchmarks now cover local Node process timings, dedicated browser worker captures, portable cross-device history import/export, and JSON artifact review gates, but they are still not isolated native Rust benchmarks.
